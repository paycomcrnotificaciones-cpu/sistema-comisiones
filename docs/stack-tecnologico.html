Aplicación para controlar las ventas y las comisiones de una empresa: cada comisionista con su libreta, sus ventas, sus metas y lo que corresponde pagar en el mes. Funciona de forma local, solo en esta laptop, y se enciende cuando el usuario lo decide.

Versión actualizada · noviembre 2026 · uso local en una sola laptop

2Estructura del proyecto

  • backend/ — API NestJS, Prisma y 11 migraciones.
  • frontend/ — web Next.js (App Router) con Tailwind CSS 4.
  • docs/ — documentación del proyecto (API, diseño, entorno, roadmap).
  • backups/ — respaldos de la base (se conservan los últimos 7).
  • logs/ — salida de la API y de la web al arrancar.
  • iniciar.sh / detener.sh / respaldo.sh — arranque, apagado y respaldo manual.
No es un monorepo: son dos proyectos independientes que se comunican por HTTP. Las validaciones compartidas viven en backend/src/common/validators.ts.

6Auth y seguridad (implementación propia, sin Passport)

  • Login con correo y contraseña; contraseñas con bcryptjs.
  • Token JWT de acceso con duración de 8 horas (sin refresh).
  • Autorización por roles con RolesGuard y el decorador @Roles(...).
  • Separación por empresa: cada consulta filtra por empresaId tomado del token.
  • Validación de entrada con Zod antes de tocar la base.
  • Auditoría global: registra quién hizo cada cambio y si salió bien o mal.
  • La API solo escucha en 127.0.0.1 y acepta pedidos únicamente desde la web local.

8Entorno de ejecución y respaldo

  • Arranque manual: ./iniciar.sh levanta el contenedor, la API y la web, y valida /api/health.
  • Apagado: ./detener.sh cierra web, API y contenedor.
  • Respaldo: ./respaldo.sh guarda un pg_dump comprimido en backups/.
  • Separación: web 3100, API 4100 (/api), base 55433.
  • No arranca solo al encender la laptop; el usuario decide cuándo.
  • La aplicación anterior quedó desactivada (no borrada) y ambos servicios no chocan de puerto.

9No usado / pendiente

  • Sin contenedores: PostgreSQL va instalado directamente en el sistema.
  • Sin Redis ni BullMQ: no hay colas; las comisiones de suscripción se generan al abrir el mes.
  • Sin Passport: la autenticación es propia con @nestjs/jwt.
  • Sin despliegue público: no hay dominio, túnel ni servidor externo.
  • Pruebas automatizadas mínimas (solo la ruta de salud); el resto se verificó a mano.
  • Sin refresh token: al vencer las 8 horas hay que volver a entrar.
